# 常见问题

## 启动后没有收到任务提醒

先看主窗口是否出现当前项目的新事件和时间。没有新事件时，先检查执行者是否真的使用本工具的状态 `--inbox`，不要先重复发送手机测试。Codex hook 还需要在对应 Codex 版本中审阅并信任；Grok 必须实际调用本机上报工具。程序不会读取聊天来猜任务进度。

主窗口启用跟进、手机渠道启用、电脑未暂停且网络可用，才会发送后续新提醒。启动或恢复时已有事件只建立基线，不补发旧消息。

## 微信发题失败或手机没有显示

1. 在机器人聊天记录中核对实际消息，通知栏可能没有显示全部内容。
2. 检查绑定是否可用，本人可给机器人发一句普通文字，刷新通信上下文。
3. 问答通道启用后会持续接收；第一次接收初始化完成前短暂显示 `paused`。如果显示接收暂停，检查绑定后点“重试接收”。
4. `-2` 表示服务拒绝，不能仅凭该码认定登录过期。刷新上下文后显式测试；若仍失败，再检查登录或服务状态。
5. `acceptance_unknown` 或网络失败没有证明消息未发出，因此程序不会重发旧编号。先核对手机；需要重新提问时，由原执行者取消旧问题并明确创建新问题。

服务受理、程序尝试发送、手机真正收到、原任务取回答案是不同步骤，不能相互替代。微信没有给出足以保证长期主动推送的上下文有效期或投递承诺。

## 微信回复没有使任务继续

发送 `八位编号 A` 或 `回复 八位编号 A`，使用这次实际收到的编号。只发 `A`、引用旧问题、写项目名或转发他人消息不会替代编号。只接收当前绑定本人的直接文字。

原执行者必须还在等待；问题最多 15 分钟有效。若等待进程已结束，文件中新出现的答案不会自动唤醒任务。可由原执行者使用同样的来源、task-id、turn-id 和 request-id 调用 `get`，不要新开会话假装回答了旧原生卡片。

免打扰、停止跟进或退出会停止新回复转交，恢复后不会补转暂停前的旧问题。请由执行者保存 checkpoint，稍后新建问题，不无限重试。

## 桌宠和独立工具能否同时打开

可以分别运行，但**不能同时接收同一个微信机器人**。本工具默认使用独立目录，不自动迁移绑定或队列。要使用原来的机器人，先关闭旧桌宠微信问答或退出旧桌宠，再在本工具中重新配置。不要共享同一个活动的 `data` 目录。

## Bark 收到状态，但不能回复

这是预期行为。Bark 仅作状态提醒备用通道；问题正文和回答由微信问答处理。微信结果不明确时不会自动在 Bark 重发，以免双发。iPhone 的专注模式、系统通知权限、网络和推送服务也会影响提示。

## 移动文件夹或分享给朋友

移动源码或 Python 环境后，重新生成并审阅 Codex hook 命令，更新执行者的工具及收件目录。不要把仍在使用的目录直接移动。

分享程序和源码时不带 `data`。加密账号绑定只供当前 Windows 用户使用，朋友应重新扫码；不要把 Token、Bark 设备地址、配置文件或真实问答记录发到聊天或公开仓库。
